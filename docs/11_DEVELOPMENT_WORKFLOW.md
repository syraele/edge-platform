# Purpose

This document defines the official development workflow for EDGE_ENGINE.

This workflow MUST govern the execution of every future milestone.

It MUST remain the reference process for planning, implementation, validation, and documentation synchronization.

# Repository First Principle

The repository MUST be the authoritative source of project knowledge.

No milestone MUST begin from conversational assumptions.

The current repository state MUST be reviewed before any implementation activity begins.

# Development Lifecycle

The official lifecycle MUST follow this sequence:

Repository Review
↓

Technical Review
↓

Implementation Plan
↓

Milestone Specification
↓

Approval
↓

Implementation
↓

Regression Testing
↓

Documentation Synchronization
↓

Commit
↓

Next Milestone

# Milestone Specification

Every milestone MUST be described through an official specification.

Each milestone specification MUST contain:

- Milestone ID
- Objective
- Motivation
- Scope
- Affected Components
- Files
- Acceptance Criteria
- Required Tests
- Documentation Updates
- Completion Checklist

The specification MUST be reviewed before implementation begins.

# Rules

One milestone MUST be worked on at a time.

No implementation MUST begin without an approved milestone specification.

No commit MUST be made without complete regression validation.

No regression MUST be considered complete without updated documentation.

# Non Goals

This document MUST NOT define architecture.

This document MUST NOT define the domain model.

This document MUST NOT define algorithms.

This document MUST NOT define implementation details.
